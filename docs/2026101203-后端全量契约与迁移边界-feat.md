## 1. 结论与事实边界

1. **334 是文档条目数，也是此源码版本的本类业务 public handler 数，但不是全部暴露面。** 18 个 API 控制器、34 条动态 API 注册，另有 **222 个框架/继承/构造函数候选**通过 public 检查；参数缺失常导致失败，不能称它们都是成功可用接口。`FileDavController` 固定 `dav` 分派不能直接暴露任意继承方法。
2. `Route::any` 真正注册 GET/HEAD/POST/PUT/PATCH/DELETE/OPTIONS；文档中的 get/post 只是注释。必须从现有客户端用法制定兼容契约，不能照 OpenAPI REST 惯例自动改为另一个接口。
3. `IndexController` 是另一套分派器，没有 public 检查，有 9 个业务方法、自己的 `__invoke`，以及 **18 个继承候选（12 public、6 protected）**。还存在 DAV、`/api/user`、Nginx 静态/应用代理、图片 404 裁剪路径、WS 和外部 SSE，不能混入“334 HTTP JSON API”后宣称全覆盖。
4. 源后端每次 `WebApi` 请求都会加载 `doo.so`。**这证明原实现存在原生依赖，不证明 FastAPI 必须复用该二进制。** 不变前端必须保留 API/PGP/WS/许可交互语义；仅在选择迁移已有用户/数据库/会话时，才额外要求旧密码与旧 token 互通。用户尚未明确选择旧数据迁移，不能把它默认为阻止全新安装的条件。
5. 无论选全新数据库或旧数据迁移，项目、任务、聊天、文件与后台任务都不是孤立 CRUD；权限、观察者、消息回执、增量删除标记、异步索引等是实质业务。仅 HTTP 成功或把表结构搬过去不是迁移完成。
6. 已保存完整静态台账和源快照；**没有取得运行中的数据库/容器/doo.so，也没有证实所有外部服务可用**。源码事实、静态推断和待采样事项在下文分开。

## 3. 真实路由、HTTP 与响应

### 3.1 分派与意外表面

- `routes/web.php:40-90` 为 API 资源注册 `Route::any`。`InvokeController.php:21-38` 拼接 method 与非空 action，以 `method_exists` + `ReflectionMethod::isPublic()`检查，之后调用 `$this->$app()`，**没有 declaring-class、static、magic 或业务白名单限制**。`__before:46-48`直接 true，API AbstractController 不增加权限。
- 文档生成器 `DocApiMap.php:75-118`反而排除了继承、static、`__`开头方法，并从 docblock 解析 HTTP。因此“文档只列334”不能推出“其余方法不能被路由触达”。17 个常规 API 控制器各继承13个 public 候选；Assistant 额外本类 public `__construct`，共222。FileDav 的10个业务方法独立计入334。
- 精确继承 public 名称：`middleware/getMiddleware/callAction/__call/authorize/authorizeForUser/authorizeResource/dispatchSync/validateWith/validate/validateWithBag/__invoke/__before`。除 `getMiddleware` 外通常有必填参数，零参数分派预期产生参数错误，而不是有用业务功能。Assistant 构造函数只检查 AI 安装态，不是用户认证。
- PHP 方法名大小写不敏感；`task__add`既可作为 `/task/add`，也可直接放入一个段 `/task__add`。源注释“最多一个双下划线”描述文档规范，不是方法字符串过滤。不能把注释当访问控制。
- `FileDavController.php:25-27`将 Laravel 传入的 action 和 route 默认 method 顺序交换，调用父分派器；`routes/web.php:64`先于普通 file 动态路由。实现时保留具体顺序，不能生成覆盖它的泛化路由。
- `IndexController.php:40-52`只用 method_exists，未知方法回到 main，`default`返回空字符串；根与最多5段页面路由在 `web.php:104-110`，四/五段排除 uploads/images。**更深的 api 路径可能落入页面回退，而不是一致404**。Index 的 inherited protected 也可由子类作用域调用；实际参数/类型可能失败。新服务必须显式 allowlist，不复制这种反射暴露。

### 3.2 正常/错误不是一个通用 JSONResponse

- `Base.php:1379-1401`：`{ret, msg, data}`，默认成功数值1、失败数值0，msg经翻译，data可数组、对象、字符串或其他实际业务值；空数组 `[]` 与 `{}` 不可随手互换。
- `bootstrap/app.php:59-64`：ApiException转 Base::retError，code进入ret；ModelNotFound转业务错误；未显式设置 HTTP status，不能统一替换成 FastAPI 422/401。`User.php:746-760`认证过期/未登录/停用使用 **ret=-1**。
- 不存在动态方法走 `Base::ajaxError:1412-1420`：**Content-Type 严格等于 `application/json`**时返回业务错误数组；否则默认HTTP404并有 `X-Error-Message-Base64`。`application/json; charset=utf-8`在源代码比较中不是相等；这是需采样的兼容边界。
- `Base::token:88-90`先 `dootask-token`，后 `token`，各自支持 header/input。WebApi记录 language、URL和PC活跃；`40-68`处理旧版本表单、PGP请求解密与响应 `{encrypted:...}`。新服务须在所有真实传输入口统一适配；multipart 分片并不总经过前端 call。
- 返回类型还包括验证码图片、纯脚本/纯文本签到、下载流、重定向、HTML页面、Office回调与DAV XML/stream。逐handler return已入机器表，不能给所有业务强套JSON envelope。
- FrontRecovery已收到以上真实HTTP与envelope；其消费者指出严格数值ret与PGP、上传旁路、WS receipt差异，见其独立前端报告。该消息是交叉线索，不代替本报告源码事实。

- **A 前端协议（必需）**：新装也需要注册/登录、过期/设备语义、`users/key/client`密钥交换、实际OpenPGP HTTP/WS、翻译、许可页面对应行为。这是外部可观察契约，不等于必须保留PHP FFI ABI。新后端可用合法标准库/维护中依赖实现标准PGP，必须与原样前端真实互操作；不可关闭加密。
- **B 旧数据互通（条件）**：若用户选择保留已有用户/密码/token/会话，则必须确定md5s实际算法与编码、token签名/格式/过期语义、原生注册DB副作用或官方兼容SDK。`md5s`名字不是算法证明，JWT库存在不是token格式证明。未选择旧数据迁移时可用新的安全密码哈希及服务端不透明token等设计，只保留前端可见形状/生命周期，不声称兼容旧数据。
- **C 许可（独立）**：不得让新装/旧装选择变成删除许可校验的理由；独立二进制的修改/分发权未获证实。可选官方有权SDK/原生库或供应方支持的协议实现；不可返回假授权、绕过激活、推测所有二进制均适用项目AGPL。

`userCreate:193-211`从原生返回envelope后查询DB，并在存在PHP事务时commit/begin；原生可能独立写DB，这是已有数据/原生复用路径的重要事务边界。C字符串没有声明free函数，内存所有权、线程安全和initialize是否进程全局均未知；贸然从ASGI并发ctypes调用可能串身份，不能在没有证据时选定该复用方案。

### 7.1 两种数据方案，不缩水功能

| DB与文件 | 最终schema、默认配置/种子，空业务数据 | 额外导入ID、关系、文件、软删除、设置、版本和增量冻结/回滚 |

### 7.2 共享接口和模型必须先定

1. `RequestContext`：request_id、actor、token/device、language、platform/version/fd、base_url、PGP上下文；ASGI contextvars隔离，后台任务显式携带必要数据，不用进程全局保存请求身份。
2. `Transport`：数字ret、翻译msg、原始data类型、业务异常映射、form/JSON/multipart、下载/重定向/HTML、PGP包装；禁止FastAPI自动校验错误直接穿透旧前端。
3. `ActorPolicy`：auth/disabled/expiry/device、admin、ProjectScope/TaskScope/FileScope/DialogScope与部门只读；业务服务拿actor与对象后判断，不以任意header伪造userid。
4. `UnitOfWork`：MariaDB事务/行锁/唯一约束/软删除、对象序列化与分页/Deleted增量；写模型与对应事件同一业务编排。事务成功后的外发必须有明确顺序，不能比DB提交更早向用户宣布变更。
5. `Collaboration`：创建project/task聊天室、成员/负责人角色同步、消息+reads/session/附件/任务引用。项目与聊天在此接口共同定稿，不凭控制器目录拆成互不相关项目。
6. `Realtime/Jobs`：稳定连接标识、user/fd映射、ignoreFd、msgId/receipt、PGP、operationResult、任务负载/延时/去重/失败与停机；任务清单22项、观察者15项全部分配。
7. `Blob/File`：元数据与字节原子变更、内容版本、分享/权限、临时文件、分片状态、DAV锁/属性、附件；源文件路径到新存储路径有显式转换合同。
8. `Integrations`：appstore/AI/Office/会议/搜索/LDAP/SMTP/友盟/许可是真实配置与服务交互；每项列版本、URL/auth、超时和原失败语义，缺制品先取证，不造mock上线。
