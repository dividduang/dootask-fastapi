## 3. 下一批独立验收命令

以下命令是交接说明，**本批均未执行**。在 PowerShell 中调用已有 WSL，不需 Windows Docker CLI：

```powershell
$compose = @('-d','Ubuntu-22.04','--exec','docker','compose',
  '--project-directory','/mnt/d/rpa/202610/dootask-fastapi',
  '--env-file','/mnt/d/rpa/202610/dootask-fastapi/.runtime/runtime.env',
  '-f','/mnt/d/rpa/202610/dootask-fastapi/.runtime/compose.yaml')

# 先检查端口及 project 下是否已有未知资源；遇冲突停止，不杀用户进程。
wsl.exe -d Ubuntu-22.04 --exec ss -ltn
Get-NetTCPConnection -State Listen -ErrorAction SilentlyContinue |
  Where-Object { $_.LocalPort -in 13306,16379 }
wsl.exe @compose ps -a

# --quiet 避免把插值后的密码打印到证据。
wsl.exe @compose config --quiet
wsl.exe @compose up -d --wait --wait-timeout 180
wsl.exe @compose ps

# 仅用本项目容器，密码通过容器环境变量传入而非明文命令参数。
wsl.exe @compose exec -T redis redis-cli ping
wsl.exe @compose exec -T mariadb healthcheck.sh --connect --innodb_initialized

# 验证完暂停本项目，不删数据卷；禁止无条件 down -v、volume prune、system prune。
wsl.exe @compose stop
```

Compose 显式配置 healthchecks；`up --wait` 的成功是服务健康条件，不等于全量业务通过。若 Windows 到 WSL loopback 端口转发不通，保留实际错误，检查既有 WSL localhost-forwarding 行为；不得擅自改系统网络、防火墙或改用用户 3306/6379。本批仅观察两个目标端口未占用，不保证下一批仍然空闲。

独立验收必须同时覆盖：

1. 原始命令、退出码、UTC、真实进程/容器、版本执行值、image ID、映射仅 `127.0.0.1`，确认没有连接已有业务库。
2. 后端从 runtime.env 读取 DB/Redis 字段；MariaDB 真实账号、schema/charset/collation/engine/timezone、事务回滚、连接拒绝与权限；不要用“TCP 可连”代替应用事务。
3. Redis 正确密码 PING 与错误/无密码拒绝，真实业务 WS/任务使用，AOF 文件及跨停止/重启读回；Redis 密码不进公开 trace。
4. 通过 FastAPI 和真实 UI 写入合成业务数据；停止并重新启动本项目两服务，保持同卷，验证 DB/Redis/应用持久化和权限负例。
5. 记录 Windows→WSL 端口路径；本批未运行服务，不能预先把可达性写成 PASS。
6. 不执行全局清理，只管理 compose project 的确切资源；保留报告所列两个固定镜像，不需要为本批导出/提交数百 MB 的镜像副本。
