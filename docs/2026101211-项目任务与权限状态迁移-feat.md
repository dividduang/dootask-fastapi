## 2. 安装合同

- 入口：`backend.domains.projects.ROUTES`。仅已知模块的显式字典合并，不以反射公开任意函数。
- 所有 handler：`handler(connection, context, data, settings)`；SQLAlchemy Core 同步 `Connection` 由调用者事务拥有。嵌套业务不 commit，不新建业务连接。
- `RESPONSE_KINDS[path] == 'data'`：返回原 data 对象/数组，调用者使用 `backend.errors.success(data)` 包络。`'Response'`：原样返回 Starlette Response，不能再包 JSON。
- 非 JSON：`project/task/filedown` 为附件文件/预览跳转；`project/task/down` 为导出 ZIP；两个 public checkin 为纯文本/安装 shell 脚本；源两个 obsolete AI generate 方法仅版本校验后空 HTTP body，明确保留这个源行为，不以它们代替实际 AI 能力。真实 AI 在 AI 后台消费者与现有消息助手接口。
- `PUBLIC_ROUTES`：公开签到（验证本域密钥）、导出下载（随机 bearer key，Files grant 到期/账户检查）、两个源 obsolete 版本检查入口。其余入口经共享 authenticate。
- 源 HTTP 通常 Route::any，别名仍由共享固定 allowlist 处理；唯一 `POST_ONLY_ROUTES={'projecttaskhandoff/assign'}` 必须由 main 检查真实请求 method。业务 data 内的伪 method 不得作为证据。
- 显式调用 `projects.register_jobs()` 一次，注册本域 jobs、project_id/task_id realtime scope；不能在 import 时启动 worker。由 Messaging worker 统一消费。
- XLS 新依赖：`xlwt==1.3.0`。本批未安装/解析锁。必须由唯一 integration owner 纳入 requirements 与锁定；依赖未满足时不能声称导出端到端完成。

## 3. 实际业务实现

### 项目、成员与权限

项目新建持久化项目/主负责人/默认或指定列/真实 project 会话及成员，工作流可选。聊天室复用 `dialog_core.create_group/sync_members`；project_users 的 0/1/2 角色同步到同一个 dialog_users，更新 owner_id。没有第二套会话实体。

负责人、副管理员、普通成员区分到具体动作：转让/删除/任命副管理员仅主负责人；成员管理和配置允许项目管理角色，副管理员不得删除其他管理角色；离职移交仅传主负责人，不继承副管理员。移交和退出同时处理任务成员、handoff、会话成员、Deleted、搜索和 WS outbox。

部门只读范围复用 Accounts 的 `managed_departments/department_users`；系统开关与项目 `department_owner_view` 联合生效。部门只读不因此取得普通写权限。Handoff 单独按 role/candidates/adjust/note 的源策略允许特定部门负责人指派，受保护负责人不可移除，并锁任务行验证 version。

权限默认值按 `ProjectPermission.php:109-120`；task_add/update/time/status/remove/archived/move 与列权限独立判断。复合修改逐项校验，避免源按第一个字段选 permission 后夹带其他操作。

### 任务、流程、增量和附件

真实任务创建/子任务、成员/协助人/指定可见人、详细内容历史、优先级、标签、时间约束、周期字段、排序、工作流流转/负责人模式/列绑定、完成约束、归档恢复、软删恢复、升级、移动和复制均沿同事务。任务可见性以 root/family 继承，ACL 同时服务详情、列表、关系、附件、日志、搜索和 realtime scope；撤权通过 Deleted + 最小 tombstone 清除前端缓存。

项目归档只在恢复时撤销 `archived_follow=1` 的任务；独立任务归档不随项目恢复。删除项目/列保留源已经归档的任务，允许源规定的相关人员处理失效项目中的遗留任务。标签/附件/模板/关系的硬删除与任务软删除分开。

时间增量兼容原 TimeRange 数组、字符串分隔、updated_at/at_after/deleted_at 及秒/毫秒时间戳；第一页提供 Deleted IDs。列表 ACL 先于 total/pagination 计算，私密任务不能因分页数量、关系标题或项目日志泄露。

任务详细内容存原 HTML 于既有 LONGTEXT，而非建立未经鉴权的 public 内容文件；返回 content/history 保持原字段。附件保存、上传和实际 blob/DAV 服务属于 Files，不复制其存储。任务 filedetail/filedown 调用 Files 的格式化/路径解析/预览 helper，先执行本域 ACL；filedetail 同事务记录 recent item。消息附件到 project_task_files 由 Files `send_files_from_path` 唯一负责；本域消息 hook 只维护任务提及关系。

### 统计、投诉和公开签到

Dashboard 按真实选中管理部门及子部门的在职非机器人、可见活动项目、主任务/全员可见、团队负责人或无负责人统计；按未完成/超期/即将到期/本周上周完成/优先级/成员阶段分布，成员任务去重，多负责人分别计入工作量。

投诉验证会话成员、真实保存举报与图片、管理员查看/处理/删除；通知管理员通过持久任务和真实 system-msg 会话消息。

公开签到保留 `function off / mode off / key error / success` 纯文本及原安装脚本模式。自动/face 各自密钥恒时比较；安装脚本对配置做 shell 引用，不能将密钥或 URL 当可执行内容。自动路由器 key 不能冒充手动/定位/face 身份。`record_checkin` 同 Connection 锁用户，处理有效窗口/跨午夜归昨/多 MAC、记录 times 和 report_time，再登记真实通知。账户 quick-command 复用同 helper。

## 4. Observer / Task 实际注册

同步 observer 编排：

| 源行为 | 实现 |
|---|---|
| Project create/update/archive/delete | 项目业务中保存、Deleted、`search.sync` 与 `push_project` |
| ProjectUser create/update/delete/transfer | `sync_project_members` / `remove_task_memberships` / `transfer_user_memberships` |
| ProjectTask create/update/archive/delete/restore | `observe_task` + `handoff_record`；当前 ACL 计算，不以旧搜索 payload 授权 |
| TaskUser / VisibilityUser / Content | 业务事务内关联更新、父子 ACL、handoff、搜索入队与撤权 tombstone |
| Message task mentions | `project_tasks.sync_message_relations(connection,message)`，双向关系且目标 ACL |

持久 job 清单：

- `projects.notify`：任务新增/时间修改/到期前后通知、PushLog 去重、真实 task-alert 消息。
- `projects.export`：管理员任务/超期统计，真实多 sheet BIFF8 `.xls`、样式、计划/实际/测试/开发/取消与超期口径，ZIP + Files bearer grant + 完成消息；无数据发源通知，不生成空成功文件。
- `projects.maintenance`：AutoArchived、AppPush 开关与 60–70 分钟窗口、周期和未领取任务投递。
- `projects.recurring`：锁复核 loop_at，复制父子任务/内容/附件/成员，重置状态与时间，刷新新周期、关闭旧周期、建立关联；同一事务避免残留副本。
- `projects.unclaimed`：真实项目待领取任务消息，私密任务不放入项目全员消息。
- `projects.ai_scan / projects.ai_analyze`：按插件、系统/项目开关/延迟/每日范围建真实 AI event，调用 Messaging 官方 provider client 和 Files vector client，记录 failed/retry/skipped/completed；建议通过真实 Markdown `:::ai-action` 消息输出，更新真实 msg_id，采纳/忽略修改该 Markdown 状态。
- `complaints.notify`：真实管理员通知。
- `checkin.notify / checkin.remind / checkin.reminder_message`：真实考勤机器人消息和提醒。Accounts 重复提醒注册已由其 owner 删除。节假日访问源官方接口，失败按源周末 fallback，写日志，不伪造 provider 结果。

周期只注册 `projects.maintenance`、`projects.ai_scan`、`checkin.remind`，均 60 秒。Index 读取统一 `jobs.SCHEDULES`，不另开一套 scheduler。

## 5. 有意修复的源风险

1. 权限设置修改原只校验项目成员；现限定项目管理角色，防自提权。
2. template_list/tag_list/task_flow、附件 only_update_at、easylists、任务关系和项目日志入口统一 ACL，防旁路读取私密对象。
3. 复合任务更新分别校验时间/状态/普通字段权限；部门只读不能通过 unowned-task 分支写任务。
4. 搜索与延迟 WS 投递使用实时 ACL；撤销消息不携带名称/内容；指定可见用户离开项目后不保留孤立 grant。
5. 相似任务建议不使用源 userid=0 的权限绕过；结果必须对当前任务所有接收人可见。
6. 签到密钥非空、恒时比较、隔离自动/face 模式；安装脚本防配置命令注入。
7. 不安装/公开源继承的反射方法，仅固定82业务入口。obsolete 方法的空 body 明确标识，不冒充 AI 实现。
