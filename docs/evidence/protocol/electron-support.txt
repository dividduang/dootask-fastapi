<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id=timeline>Timeline<a href=#timeline class=hash-link aria-label="Direct link to Timeline" title="Direct link to Timeline" translate=no>​</a></h2>
<p><a href=https://releases.electronjs.org/schedule target=_blank rel="noopener noreferrer" class="">Electron's Release Schedule</a> lists a schedule of Electron major releases showing key milestones including alpha, beta, and stable release dates, as well as end-of-life dates and dependency versions.</p>
<div class="theme-admonition theme-admonition-info admonition_xJq3 alert alert--info"><div class=admonitionHeading_Gvgb><span class=admonitionIcon_Rf37><svg viewBox="0 0 14 16"><path fill-rule=evenodd d="M7 2.3c3.14 0 5.7 2.56 5.7 5.7s-2.56 5.7-5.7 5.7A5.71 5.71 0 0 1 1.3 8c0-3.14 2.56-5.7 5.7-5.7zM7 1C3.14 1 0 4.14 0 8s3.14 7 7 7 7-3.14 7-7-3.14-7-7-7zm1 3H6v5h2V4zm0 6H6v2h2v-2z"/></svg></span>info</div><div class=admonitionContent_BuS1><p>Electron's official support policy is the latest 3 stable releases. Our stable
release and end-of-life dates are determined by Chromium, and may be subject to
change. While we try to keep our planned release and end-of-life dates frequently
updated here, future dates may change if affected by upstream scheduling changes,
and may not always be accurately reflected.<p>See <a href=https://chromiumdash.appspot.com/schedule target=_blank rel="noopener noreferrer" class="">Chromium's public release schedule</a> for
definitive information about Chromium's scheduled release dates.</div></div>
<p>Electron's cadence between major version releases is 8 weeks long. Before each major
version hits stable, it goes through a four-week <strong>alpha</strong> phase and a four-week
<strong>beta</strong> phase.</p>
<!-- -->
<p><strong>Notes:</strong></p>
<ul>
<li class="">Alphas are generally less stable than beta releases. The cutoff between the two
corresponds to when the underlying Chromium version enters Chrome's Beta channel.</li>
<li class="">The <code>-alpha.1</code>, <code>-beta.1</code>, and <code>stable</code> dates are our solid release dates.</li>
<li class="">We strive for weekly alpha/beta releases, but we often release more than scheduled.</li>
<li class="">All dates are our goals but there may be reasons for adjusting the stable deadline, such as security bugs.</li>
</ul>
<p><strong>Historical changes:</strong></p>
<ul>
<li class="">Since Electron 5, Electron has been publicizing its release dates (<a href=https://www.electronjs.org/blog/electron-5-0-timeline target=_blank rel="noopener noreferrer" class="">see blog post</a>).</li>
<li class="">Since Electron 6, Electron major versions have been targeting every other Chromium major version. Each Electron stable should happen on the same day as Chrome stable (<a href=https://www.electronjs.org/blog/12-week-cadence target=_blank rel="noopener noreferrer" class="">see blog post</a>).</li>
<li class="">Since Electron 16, Electron has been releasing major versions on an 8-week cadence in accordance to Chrome's change to a 4-week release cadence (<a href=https://www.electronjs.org/blog/8-week-cadence target=_blank rel="noopener noreferrer" class="">see blog post</a>).</li>
<li class="">Electron temporarily extended support for Electron 22 until October 10, 2023, to support an extended end-of-life for Windows 7/8/8.1</li>
</ul>
<h2 class="anchor anchorTargetStickyNavbar_Vzrq" id=version-support-policy>Version support policy<a href=#version-support-policy class=hash-link aria-label="Direct link to Version support policy" title="Direct link to Version support policy" translate=no>​</a></h2>
<p>The latest three <em>stable</em> major versions are supported by the Electron team.</p>
<p>For example, if the latest release is 42.1.x, then the 41.0.x as well
as the 40.2.x series are supported. We only support the latest minor release
for each stable release series. This means that in the case of a security fix,
42.1.x will receive the fix, but we will not release a new version of 42.0.x.</p>
<p>The latest stable release unilaterally receives all fixes from <code>main</code>,
and the version prior to that receives the vast majority of those fixes
as time and bandwidth warrants. The oldest supported release line will receive
only security fixes directly.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id=chromium-version-support>Chromium version support<a href=#chromium-version-support class=hash-link aria-label="Direct link to Chromium version support" title="Direct link to Chromium version support" translate=no>​</a></h3>
<div class="theme-admonition theme-admonition-tip admonition_xJq3 alert alert--success"><div class=admonitionHeading_Gvgb><span class=admonitionIcon_Rf37><svg viewBox="0 0 12 16"><path fill-rule=evenodd d="M6.5 0C3.48 0 1 2.19 1 5c0 .92.55 2.25 1 3 1.34 2.25 1.78 2.78 2 4v1h5v-1c.22-1.22.66-1.75 2-4 .45-.75 1-2.08 1-3 0-2.81-2.48-5-5.5-5zm3.64 7.48c-.25.44-.47.8-.67 1.11-.86 1.41-1.25 2.06-1.45 3.23-.02.05-.02.11-.02.17H5c0-.06 0-.13-.02-.17-.2-1.17-.59-1.83-1.45-3.23-.2-.31-.42-.67-.67-1.11C2.44 6.78 2 5.65 2 5c0-2.2 2.02-4 4.5-4 1.22 0 2.36.42 3.22 1.19C10.55 2.94 11 3.94 11 5c0 .66-.44 1.78-.86 2.48zM4 14h5c-.23 1.14-1.3 2-2.5 2s-2.27-.86-2.5-2z"/></svg></span>tip</div><div class=admonitionContent_BuS1><p>Chromium's public release schedule is <a href=https://chromiumdash.appspot.com/schedule target=_blank rel="noopener noreferrer" class="">here</a>.</div></div>
<p>Electron targets Chromium even-number versions, releasing every 8 weeks in concert
with Chromium's 4-week release schedule. For example, Electron 26 uses Chromium 116, while Electron 27 uses Chromium 118.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id=nodejs-version-support>Node.js version support<a href=#nodejs-version-support class=hash-link aria-label="Direct link to Node.js version support" title="Direct link to Node.js version support" translate=no>​</a></h3>
<p>Electron upgrades its <code>main</code> branch to even-number versions of Node.js when they enter Active LTS. The schedule
is as follows:</p>
<img src="https://raw.githubusercontent.com/nodejs/Release/main/schedule.svg?sanitize=true" alt=Releases />
<p>If Electron has recently updated its <code>main</code> branch to a new major version of Node.js, the next stable
branch to be cut will be released with the new version.</p>
<p>Stable release lines of Electron will receive minor and patch bumps of Node.js after they are released.
Patch bumps to Node.js will be released in patch releases of Electron, and minor bumps to Node.js will result in a minor release of Electron.
Security-only release branches will receive security-related changes from Node.js releases, but not the full release.</p>
<h3 class="anchor anchorTargetStickyNavbar_Vzrq" id=breaking-api-changes>Breaking API changes<a href=#breaking-api-changes class=hash-link aria-label="Direct link to Breaking API changes" title="Direct link to Breaking API changes" translate=no>​</a></h3>
<p>When an API is changed or removed in a way that breaks existing functionality, the
previous functionality will be supported for a minimum of two major versions when
possible before being removed. For example, if a function takes three arguments,
and that number is reduced to two in major version 10, the three-argument version would
continue to work until, at minimum, major version 12. Past the minimum two-version
threshold, we will attempt to support backwards compatibility beyond two versions
until the maintainers feel the maintenance burden is too high to continue doing so.</p>
