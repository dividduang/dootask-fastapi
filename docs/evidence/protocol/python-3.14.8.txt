        <header class="article-header">
            <h1 class="page-title">Python 3.14.8</h1>
        </header>

        
        

        

        <p><strong>Release date:</strong> Sept. 30, 2026</p>

        
        <p><img width="538" height="507" src="https://hugovk.dev/python-3.14.png" alt="Two snakes enjoying a pie with 3.14 on the top and π crimping"></p>
<h2>This is the eighth maintenance release of Python 3.14</h2>
<p>Python 3.14.8 is an expedited security release and the eighth maintenance release of 3.14, containing around 354 bugfixes, build improvements and documentation changes from 142 contributors since 3.14.7.</p>
<h2>Security content in this release</h2>
<ul>
<li>
<p><a href="https://www.cve.org/CVERecord?id=CVE-2026-19445" rel="noopener noreferrer">CVE-2026-19445</a> <a href="https://github.com/python/cpython/issues/156293" rel="noopener noreferrer">gh-156293</a> Use-after-free of a server-side <code>SSLContext</code> when <code>sni_callback</code> switches contexts</p>
</li>
<li>
<p><a href="https://www.cve.org/CVERecord?id=CVE-2026-19553" rel="noopener noreferrer">CVE-2026-19553</a> <a href="https://github.com/python/cpython/issues/156793" rel="noopener noreferrer">gh-156793</a> <code>SSLContext.wrap_bio()</code> missing validation of server_hostname parameter</p>
</li>
<li>
<p><a href="https://www.cve.org/CVERecord?id=CVE-2026-15310" rel="noopener noreferrer">CVE-2026-15310</a> <a href="https://github.com/python/cpython/issues/156002" rel="noopener noreferrer">gh-156002</a> Memory exhaustion in <code>zipfile</code> in bzip2/LZMA/Zstandard decompression</p>
</li>
<li>
<p><a href="https://www.cve.org/CVERecord?id=CVE-2026-19672" rel="noopener noreferrer">CVE-2026-19672</a> <a href="https://github.com/python/cpython/issues/155999" rel="noopener noreferrer">gh-155999</a> <code>tarfile</code> extraction filter bypass allows creation of directories outside the destination</p>
</li>
<li>
<p><a href="https://www.cve.org/CVERecord?id=CVE-2026-15806" rel="noopener noreferrer">CVE-2026-15806</a> <a href="https://github.com/python/cpython/issues/155694" rel="noopener noreferrer">gh-155694</a> <code>urllib.request.HTTPPasswordMgr</code> credentials for one URL scheme sent over another scheme</p>
</li>
<li>
<p><a href="https://www.cve.org/CVERecord?id=CVE-2026-17084" rel="noopener noreferrer">CVE-2026-17084</a> <a href="https://github.com/python/cpython/issues/155292" rel="noopener noreferrer">gh-155292</a> <code>StringPrep</code> algorithm considered Unicode codepoint attributes outside Unicode 3.2.0</p>
</li>
<li>
<p><a href="https://github.com/python/cpython/issues/158446" rel="noopener noreferrer">gh-158446</a> Reject float format precision near <code>INT_MAX</code></p>
</li>
<li>
<p><a href="https://github.com/python/cpython/issues/157953" rel="noopener noreferrer">gh-157953</a> Update bundled Expat to <a href="https://blog.hartwork.org/posts/expat-2-8-5-released/" rel="noopener noreferrer">2.8.5</a></p>
</li>
<li>
<p><a href="https://github.com/python/cpython/issues/158010" rel="noopener noreferrer">gh-158010</a> Update bundled OpenSSL to <a href="https://openssl-library.org/news/secadv/20260929.txt" rel="noopener noreferrer">3.5.9</a> for Windows, macOS, Android and iOS</p>
</li>
</ul>
<p>Python 3.14 is not affected by <a href="https://www.cve.org/CVERecord?id=CVE-2026-82049" rel="noopener noreferrer">CVE-2026-82049</a> (<a href="https://github.com/python/cpython/issues/157190" rel="noopener noreferrer">gh-157190</a>, <code>tarfile</code> hard link to symlink), which is fixed in the 3.10–3.13 releases: since Python 3.14.0b1, <code>os.link()</code> follows symbolic links (<a href="https://github.com/python/cpython/issues/81793" rel="noopener noreferrer">gh-81793</a>), which already prevented it.</p>
<h2>Attention macOS 27.0 <code>IDLE</code> or <code>tkinter</code> users</h2>
<p>When running IDLE or other GUI applications that use the <code>tkinter</code> module, these applications may hang when using an application's menu command that opens a dialog (for example, IDLE's <code>About IDLE</code>, <code>Settings</code>, and <code>Open Module</code> commands) resulting in a spinning beach ball with <code>Force Quit</code> needed.</p>
<p>This problem is due to an operating system behavior change in macOS 27.0 that is believed to affect all current versions of the Tk graphics toolkit and thus the <code>tkinter</code> module in all current Python versions.</p>
<p>If you depend on Tk-based applications (like IDLE) on macOS, you may want to consider deferring installing macOS 27.0 until a Tk or macOS workaround is available or testing that your application workflow is not affected. Follow issue <a href="https://github.com/python/cpython/issues/158053" rel="noopener noreferrer">#158053</a> for updates.</p>
<h2>Major new features of the 3.14 series, compared to 3.13</h2>
<p>Some of the major new features and changes in Python 3.14 are:</p>
<h3>New features</h3>
<ul>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-free-threaded-now-supported" rel="noopener noreferrer">PEP 779</a>:  Free-threaded Python is officially supported</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-deferred-annotations" rel="noopener noreferrer">PEP 649</a>: The evaluation of annotations is now deferred, improving the semantics of using annotations.</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#pep-750-template-string-literals" rel="noopener noreferrer">PEP 750</a>: Template string literals (t-strings) for custom string processing, using the familiar syntax of f-strings.</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#pep-734-multiple-interpreters-in-the-standard-library" rel="noopener noreferrer">PEP 734</a>: Multiple interpreters in the stdlib.</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#pep-784-zstandard-support-in-the-standard-library" rel="noopener noreferrer">PEP 784</a>: A new module <code>compression.zstd</code> providing support for the Zstandard compression algorithm.</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#pep-758-allow-except-and-except-expressions-without-brackets" rel="noopener noreferrer">PEP 758</a>: <code>except</code> and <code>except*</code> expressions may now omit the brackets.</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-pyrepl-highlighting" rel="noopener noreferrer">Syntax highlighting in PyREPL</a>, and support for color in <a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-color-unittest" rel="noopener noreferrer">unittest</a>, <a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-color-argparse" rel="noopener noreferrer">argparse</a>, <a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-color-json" rel="noopener noreferrer">json</a> and <a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-color-calendar" rel="noopener noreferrer">calendar</a> CLIs.</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#pep-768-safe-external-debugger-interface" rel="noopener noreferrer">PEP 768</a>: A zero-overhead external debugger interface for CPython.</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#uuid" rel="noopener noreferrer">UUID versions 6-8</a> are now supported by the <code>uuid</code> module, and generation of versions 3-5 are up to 40% faster.</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#pep-765-control-flow-in-finally-blocks" rel="noopener noreferrer">PEP 765</a>: Disallow <code>return</code>/<code>break</code>/<code>continue</code> that exit a <code>finally</code> block.</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-capi-config" rel="noopener noreferrer">PEP 741</a>: An improved C API for configuring Python.</li>
<li>A <a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-tail-call-interpreter" rel="noopener noreferrer">new type of interpreter</a>. For certain newer compilers, this interpreter provides significantly better performance. Opt-in for now, requires building from source.</li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#improved-error-messages" rel="noopener noreferrer">Improved error messages.</a></li>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#hmac" rel="noopener noreferrer">Builtin implementation of HMAC</a> with formally verified code from the HACL* project.</li>
<li>A <a href="https://docs.python.org/3/whatsnew/3.14.html#asyncio-introspection-capabilities" rel="noopener noreferrer">new command-line interface</a> to inspect running Python processes using asynchronous tasks.</li>
<li>The pdb module now supports <a href="https://docs.python.org/3/whatsnew/3.14.html#pdb" rel="noopener noreferrer">remote attaching to a running Python process</a>.</li>
</ul>
<p>For more details on the changes to Python 3.14, see <a href="https://docs.python.org/3/whatsnew/3.14.html" rel="noopener noreferrer">What’s new in Python 3.14</a>.</p>
<h3>Build changes</h3>
<ul>
<li><a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-no-more-pgp" rel="noopener noreferrer">PEP 761</a>: Python 3.14 and onwards no longer provides PGP signatures for release artifacts. Instead, Sigstore is recommended for verifiers.</li>
<li>Official macOS and Windows release binaries include an <a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-jit-compiler" rel="noopener noreferrer"><em>experimental</em> JIT compiler</a>.</li>
<li>Official <a href="https://docs.python.org/3/whatsnew/3.14.html#whatsnew314-build-changes" rel="noopener noreferrer">Android binary releases</a> are now available.</li>
</ul>

<li>C API <a href="https://docs.python.org/3/whatsnew/3.14.html#removed-c-apis" rel="noopener noreferrer">removals</a> and <a href="https://docs.python.org/3/whatsnew/3.14.html#deprecated-c-apis" rel="noopener noreferrer">deprecations</a></li>

The JSON file available for download contains the list of all the installable packages available as part of this release, including file URLs and hashes, but is not required to install the latest release. The traditional installer will remain available throughout the 3.14 and 3.15 releases.</p>
