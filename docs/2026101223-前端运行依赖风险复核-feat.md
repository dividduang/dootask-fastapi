### 3.3 Markdown/linkify：顶层已修；主题内还有可达旧算法

- 当前顶层 **markdown-it14.3.2、linkify-it5.0.2**并不命中下述旧范围，不该因audit聚合标签把它们一概定成high。
- [smartquotes GHSA-6v5v-wf23-fmfq](https://github.com/advisories/GHSA-6v5v-wf23-fmfq)范围markdown-it≤14.1.1，首修14.2.0；必须typographer=true。生产 `@kangc`第22行真实存在 `u.substr(0,l)+f+u.substr(l+1)`按每个quote重建字符串，Vuepress theme默认 `typographer:true`；**算法与消费条件可达**。XSS过滤在parser之后，不会修CPU消耗。影响浏览者主线程，未测本站限长/实际耗时，不照抄advisory的Node秒数当本站测量。
- [markdown linkify GHSA-253c-mchw-3w2r](https://github.com/advisories/GHSA-253c-mchw-3w2r)完整范围 `<14.3.1` 或 `=15.0.0`，首修14.3.1/15.0.1；[linkify GHSA-v245-v573-v5vm](https://github.com/advisories/GHSA-v245-v573-v5vm)≤5.0.1，首修5.0.2。前提linkify=true或直接test/match。应用MarkdownConver和Vuepress实际 `linkify:false`，没有发现其他显式开启路径，**当前所审配置不满足该运行条件**；旧实现存在不是已执行证明。
- editor lib/theme是上游预打包JS，包含其自己的parser，不是新lock嵌套12.3.2的源文件自动替代。**只override npm嵌套markdown-it/linkify版本或只升级已安全顶层包，不能消除已读的主题内旧算法**。

最小配置方案：在engine editor、preview现有theme `extend(md)`入口仅对该parser `md.disable('smartquotes')`（保留其他typographer替换），无需重写Markdown界面；这会改变直引号→弯引号排版，需用户批准额外源码例外。若必须保持排版，就要采用已修parser生成对应主题制品/官方相容编辑器包，重新绑定实际emit并运行内容兼容，不能在未证版本上给一个虚假的“lock-only patch”。安全顶层保持14.3.2/5.0.2即可，未请求全Vue升级。

| `report/detail`→ReportDetail currentDetail.content | 第45行直接v-html，无render-time sanitizer | **sink可达，服务端净化未证**；仅更新TinyMCE不会保护绕过编辑器提交/旧持久内容或其他客户端。 |
| AI/消息长文→DialogMarkdown→MarkdownConver | markdown-it html=true；formatMsg删除link/script/style标签，但保留其他HTML、event attributes、raw链接属性；dootask深链需保留 | **不是完整HTML sanitizer**。用户/机器人/AI内容不能因标记“AI回复”成为同源可信代码；真实外部AI环境缺失不计漏洞成功或安全通过。 |
| TEditorTask inline初始DOM | TEditor第5行v-html content，editor稍后初始化；valid_elements只在editor解析使用 | 防护时间边界不同，不能把白名单当初始插入已安全的证据。 |

此处不给这些保留源行为硬贴“新引入CVE”；它们是本次公网门禁的**未关闭信任边界**。PM须明确允许哪些HTML/协议，而不是删富文本功能掩盖问题。若服务端已有充分净化，可保持源码不变，但需owner提供真实跨用户保存→读回→DOM断言；本报告未审backend，不给未观察净化PASS。

若授权前端防护，可用已有公共render入口把**字符串HTML在最终sink前**净化，同时覆盖nostyle、report与inline初始插入；不要仅修一个页面。拟选官方DOMPurify **3.4.16**：2026-09-23 release，gitHead与上游`purify.js`SHA256 `acefba6ebc9733869f60c80b519eaefad1691ea56022c54a3e6cbe74286d8d46`由[官方release API](https://api.github.com/repos/cure53/DOMPurify/releases/tags/3.4.16)给出（未本地下载验证）。这不是当前应用已启用的顶层2.5.9，也不是把新库放lock就完成防护。

其[最新IN_PLACE advisory](https://github.com/advisories/GHSA-6688-9rhm-gjv2)≤3.4.15首修3.4.16要求Node+IN_PLACE+删除rawtext根再序列化重解析；拟使用字符串输入/输出，不应扩大为活DOM IN_PLACE、unsafe hook或SAFE_FOR_TEMPLATES/RETURN_DOM模式。功能白名单须保留合法格式、图片、KaTeX与dootask://深链，不能“sanitize后再拼接可执行属性”。引入净化可能移除原可呈现内容，**属于前端行为修改，需用户授权**；并不能消除Mermaid后置渲染和parser DoS。

### 3.5 KaTeX、ECharts、Vue：分清额外条件，不以总数强迫major

- KaTeX CDN实际 **0.11.1**，默认trust=false；应用无trust override。`includegraphics`/URL协议两个GHSA范围 `>=0.11.0 <0.16.10`，但官方说明须trust启用/错误协议blocklist才能达对应危险路径，**当前条件不满足**。首修0.16.10，保trust=false是官方缓解。`edef` DoS范围 `>=0.12.0 <0.16.10`、`htmlData`范围 `>=0.12.0 ≤0.16.20`，**不包括该0.11.1动态资源**；不要拿npm0.13.24范围直接套它。
- [KaTeX GHSA-238p-pmpm-9mq7](https://github.com/advisories/GHSA-238p-pmpm-9mq7)范围 `>=0.11.0 <0.18.2`，首修0.18.2，但要求已有其他原型污染或受控options prototype，加上未净化的DOM插入；KaTeX本身不是污染源。现原型污染链**未证**。应用DialogMarkdown侧与VMEditor侧后置净化情况不同，不能一律称安全。若政策要求消掉这个read-side gadget，0.18.2是该项官方最低版本，需CSS/fonts和输出保真回归及授权；0.16.10并不修这项。
- ECharts5.6.0的[GHSA-fgmj-fm8m-jvvx](https://github.com/advisories/GHSA-fgmj-fm8m-jvvx)要求Lines series+tooltip+无自定义formatter+攻击data.name，首修6.1.0。所审唯一dashboard消费者只注册PieChart并type=pie；源码搜索无Lines使用，**当前该条件不可达（限定搜索范围）**，不为此直接major升图表。
- Vue2.6.14的parseHTML ReDoS及vue-template-compiler advisory还需把攻击者字符串送入模板编译路径；当前app render h(App)及固定模板、SFC构建，与v-html不是同一个路径。未发现用户字符串作为Vue模板编译，**未证明当前该advisory运行可达**；Vue2生命周期/维护风险另记，不拿它当“必须升级全部Vue”的依据。

## 4. 可接受的非运行例外与不能偷换的例外

1. **jsPDF2.5.2当前Web不可达**：未找到应用import/调用，manifest没有emitted。官方[路径遍历GHSA-f8cm](https://github.com/advisories/GHSA-f8cm-6447-x5h2)只影响Node构建及攻击者路径，首修4.0.0，不能说浏览器因此读本机任意文件；[新窗口GHSA-wfv2](https://github.com/advisories/GHSA-wfv2-pwc8-crg5)确为浏览器HTML注入，但须output特定overload及可控filename/viewer URL，当前无consumer。未来启用这些API时4.2.1是该组当前最低修复候选、或严格净化options；现不为清audit数强升此major。桌面/第三方导出不在该否定范围。
2. **npm Mermaid8.14.0→DOMPurify2.3.5等未emitted节点**可以在当前Web运行清单记非运行例外，但实际独立10.9.1动态资源仍阻断；嵌套critical [p3vf](https://github.com/advisories/GHSA-p3vf-v8qc-cwcr)范围<2.4.2，**不命中独立bundle内3.0.9**。这不减免3.0.9其他确实命中的mXSS条件。
3. **纯构建/开发服务问题**：esbuild dev-server、Vite fs.deny/HMR/launch-editor、watchpack/chokidar、PostCSS/glob/TOML工具输入等，当前由FastAPI服务已生成public，不是在线compiler/dev-server。可在“生产不运行这些服务、不开放node_modules、不构建攻击者输入”条件下不要求此批修改。开发机/CI风险不等于消失；原vite.config serve host=0.0.0.0，不能未来在公网启dev后沿用豁免。
4. **bundler漏洞并非天然build-only**：Rollup [gcx4](https://github.com/advisories/GHSA-gcx4-mw62-g8wm)、Vite [64vr](https://github.com/advisories/GHSA-64vr-g452-qvp3)可把currentScript gadget写进cjs/iife/umd输出，且需要攻击者named HTML。当前Vite app为ES modules，未满足该生成格式条件；不能因package在devDependencies就一概豁免所有已生成/预编译第三方bundle。其他静态UMD仅作范围外/条件未证，不自动PASS。
5. npm把本应用几乎所有浏览器依赖列在devDependencies，“npm audit --omit=dev零项”不构成浏览器安全证据。65个package finding是含传递传播的聚合，不是65个可达独立CVE；本报告按生产制品/消费者判定，不清总数、不删功能。
