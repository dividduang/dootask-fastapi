# 独立身份与授权清洁切换

日期：2026-10-12。有效依据：1215独立部署决策；后续用户明确批准**仅移除原厂授权界面/购买/试用入口及商业提示**的前端例外。源 `D:/rpa/202610/dootask` 未写入。此报告是实施交接，**不是运行验收或浏览器交付完成证明**。

## 实际代码切换

- `auth.create_account`成为本地注册、管理员创建/逐行导入、LDAP首次绑定建号、用户机器人和系统机器人共同创建原语。保留独立scrypt凭据、随机token、代次、会话撤销、注册开关/邀请/密码规则及main既有数据库限流。人类账号拒绝保留域`@bot.system`，机器人只有受认证创建入口/内部白名单。
- `accounts.sql`新增事务单例`account_identity_state`。所有身份创建先锁该行；首个人类账号原子记录`owner_userid`并赋admin；机器人不获取admin；删除账号不会清空初始化标记、不会因账号数归零重新授予admin。管理员创建不受公开注册关闭/邀请码约束，但仍必须通过真正管理员认证。
- 创建同一Connection写用户、auth_credentials、个人项目/owner/default列/聊天室/项目日志；项目搜索及按权限的project add推送持久化。管理员部门加入复用组织setter；已有全员群自动加入、入群notice/member hook/groupJoin/groupUpdate均在原业务事务中；没有凭空创建不存在的全员群。用户search与onboard分为独立outbox，外部appstore失败不会吞掉搜索任务。
- 管理员重置密码、bot token命令、用户删除/变更/撤销统一先锁目标users再处理凭据和设备。本人改密/认证保持同顺序。锁后重读目标，停用通过`auth.is_disabled`统一为identity含disable **或**disable_at非空；QR、机器人、后台命令、交接也收敛。HTTP/realtime共享整合由IntegrationOwner负责。
- LDAP启用且账号缺失/已有ldap身份时真实目录查询和用户DN bind；首次成功绑定可真实建号，无私有原生调用。非唯一属性、目录和本地邮箱冲突、空密码/失败bind拒绝；本地同步真实add，失败日志不冒充成功；LDAP改密先旧密码bind再required update，新本地代次撤销原session。没有把旧私库hash/token兼容带进新库。

## 邮件与事务合同

`auth.login(..., *, settings, registration=False, invite='')`正常返回用户数据；邮件政策要求未验证账号时返回精确值对象`EmailVerificationRequired(message,data)`，不是ApiError。此分支只持久化真实注册/验证记录和`accounts.verify_email` outbox，不签发session。主transport仅识别该值对象，在事务正常退出后返回原ret=0/code=email；其他ApiError、DB错误仍回滚，不提交被拒绝业务。

SMTP配置缺失在创建事务中报错并回滚。实际SMTP由job发送，失败保存在共享outbox attempts/last_error并重试，没有伪造“已发送”。验证记录30分钟有效，一次消费并核对当前用户邮箱/停用；失效或已消费job不再发送。其他账号邮件操作保留真实同步SMTP失败语义。验证用SMTP/LDAP服务器及测试邮箱仍须集中验收提供，不以fixture绕过。

`auth.change_password(..., *, settings)`现在接受实际LDAP所需settings。新任务`accounts.created`、`accounts.verify_email`由既有`accounts.register_jobs()`装入；main/init/依赖锁由唯一IntegrationOwner负责，已直接交接口。

LDAP更新属于真实外部作用，不能与MariaDB承诺分布式原子提交；目录成功后DB提交失败的运维恢复须集中负例验证，未声称可以回滚目录。普通本地用户改密也按既有配置尝试真实目录更新；未开启LDAP不联网。

## 无设备短服务token

源BotReceiveMsgTask使用generateTokenNoDevice；本次改为`auth.issue_service_token(connection,userid,context)`：随机48字节token，只存digest，purpose=service、device_id=NULL、硬上限1小时，不新增或回收交互设备。authenticate只对明确service类型放宽设备要求，仍验证账号、停用、代次、邮箱、过期、撤销和1小时上界；其他purpose必须是interactive且有有效设备。服务token不得refresh、改密、改邮箱或确认QR换取长寿命交互session。交互设备注销/撤销同时撤销同账号service；直接service logout撤销自身；账户全撤销覆盖没有device的service。security.sql/realtime/messaging_jobs改动由IntegrationOwner落地，WS明确拒绝service token。
