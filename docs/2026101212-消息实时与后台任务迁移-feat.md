## 事务、推送与失败语义

业务事务写消息、reply/forward 计数、session、实际 reads、附件、任务关系与 outbox。拒绝权限先于事件登记。worker 使用 `FOR UPDATE SKIP LOCKED`、嵌套 savepoint；失败回滚 handler SQL，保留 attempts/last_error/下次执行时间。未知 kind 真实失败，不吞掉任务。Redis publish 只是唤醒，socket 同时查询已提交投递行；即使 publish 早于提交或信号丢失，也不把“广播一次”当完成。

每个在线 fd 有独立投递与 msgId；直接指定 fd 的页面操作不跨重连补发。按用户投递的未确认消息可在旧连接租约消失后交给同账号新连接。receipt 只能确认当前已认证用户、目标 fd 与真实 msgId。共享 crypto 负责真实 OpenPGP；dialog frame 在连接要求 PGP 后加密。WS 重新认证时清除 RequestContext.actor 缓存，避免已撤销身份被连接快照长期放行。

停机设置 stop event，等待正在运行的同步工作结束。外部 HTTP/SMTP 不属于 MariaDB 原子事务；崩溃可能导致重复发送，这是明确的至少一次语义。Webhook 携带 Idempotency-Key，不能假定外部插件已经支持去重。

## 权限与共享对象

- `dialog_core.can_view_dialog` 复用 Projects 的项目/任务可见性；部门只读不能发送消息。普通群/单聊要求成员身份。
- `register_scope(name,checker)` 用于 Files/Reports/Projects 的投递前资源复验；未知 scope 拒绝。
- **删除/撤权不带 scope 的唯一合理例外：同一加锁事务中捕获原授权接收人，载荷只含必要对象 ID。** 禁止把完整敏感对象放在 unscoped 推送中绕过撤权；此条列入独立安全验收。
- Files 拥有实体字节、下载能力及 task attachment；消息文件上传复用 `files_collaboration.send_files_from_path`。录音、长文、地图、助手图片复用真实 generic_upload，而非写进私有 storage 后返回无法访问的伪 URL。
- `scope_assets` 把消息内下载能力复制成当前 dialog 范围的 grant，转发先验证原 grant 所有者或原会话权限。附件 cursor 为 schema 的数据库生成列，不重复写入。
- Projects 的 `sync_message_relations` 接入新增/编辑/撤回；新增/编辑/撤回发真实 `search.sync`。
- Accounts 的 preview_message、SMTP、bot command/checkin、会议消费者被直接复用，未建立第二套用户/文件/项目对象。
- `trusted_sender=True` 是内部业务能力，HTTP 不读取此参数，仅用于合法 bot 提醒/会议显示发送者；仍按真实会话成员生成接收人。
